## 2024-03-24 - [SaleNotifier Reconciliation Optimization]
**Learning:** `SaleNotifier._reconcileSales` suffered from an N+1 query and write bottleneck during startup. It sequentially checked missing records against the DB via `getSale()` and individually applied them via `applyEvent()`. Replacing this with an O(1) in-memory comparison against the pre-loaded `state` array and a single batch `upsertSales` dramatically reduces drift/SQLite roundtrips, continuing the pattern established in `PaymentNotifier`.
**Action:** When reconciling an event log against local state, always pre-load the local state to build an O(1) lookup set (e.g., `Set<String> existingIds = state.map((s) => s.id).toSet();`), filter missing events purely in-memory, map them to models, and use Drift's `batch` API (`InsertMode.insertOrReplace`) for a single mass insertion.
